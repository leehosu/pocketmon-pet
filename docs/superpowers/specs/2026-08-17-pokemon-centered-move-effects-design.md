# 포켓몬 중심 기술 이펙트 설계

작성일: 2026-08-17

## 목표

- 실제 앱과 검수 페이지 모두 선택된 골드판 포켓몬을 화면 중앙에 표시한다.
- 모든 기술은 포켓몬 몸 중앙에서 시작해 화면 전체로 확산한다.
- 기술 연출은 포켓몬 크리스탈 원본 배틀 애니메이션 오브젝트만 사용한다.
- 십자 조준선, 임의 벡터 선, 원형 링, 절차적 글로우와 가짜 타겟을 제거한다.
- 포켓몬과 기술 이외 영역은 항상 완전 투명하게 유지한다.

## 비목표

- 상대 포켓몬 또는 전투 UI를 추가하지 않는다.
- 기술의 대미지 계산, 명중 판정, 배틀 시스템을 구현하지 않는다.
- 포켓몬 스프라이트를 새로 그리거나 보간 애니메이션을 생성하지 않는다.
- 부화·진화 연출은 이번 범위에서 바꾸지 않는다.

## 확정한 배치 규칙

포켓몬은 모든 기술에서 화면 정중앙에 고정한다. 별도 타깃이나 오른쪽 발사 지점을
만들지 않고 원본 오브젝트가 몸 중앙에서 시작해 화면 전체로 확산한다.

| 분류 | 배치 | 대상 기술 |
|---|---|---|
| 방출·투사 | 몸 중앙에서 시작해 화면 전체로 확산 | 잎날가르기, 독가루, 솔라빔, 불꽃세례, 연막, 스피드스타, 화염방사, 불대문자, 물대포, 하이드로펌프, 전기쇼크, 10만볼트, 번개 |
| 자기 강화·회복 | 몸 중앙에서 시작해 주변과 화면 전체로 확산 | 광합성, 빛의장막, 천사의키스, 전기자석파 |
| 근접·신체 | 몸 중앙에서 타격 후 화면 전체로 충격 확산 | 누르기, 화염바퀴, 물기, 냉동펀치, 겁나는얼굴, 베어가르기, 전광석화 |

상대 좌표는 만들지 않는다. 모든 기술은 몸 중앙에서 원본 프레임 순서대로 시작하고
동적 확대를 통해 화면 전체에서 완결된다.

## 원본 오브젝트 전용 규칙

허용하는 시각 요소는 다음 두 종류뿐이다.

1. PokeAPI `generation-ii/gold` 포켓몬 스프라이트
2. `pret/pokecrystal`의 배틀 애니메이션 그래픽 시트와 OAM 조합

Canvas는 원본 비트맵의 이동, 회전, 반전, 알파, 크기 조절과 레이어 합성에만 쓴다.
기술을 표현하기 위한 `lineTo`, 절차적 원·십자·링, 그라디언트, 수제 다각형은 쓰지
않는다. 원본 타격, 속도선, 번개, 물줄기, 불꽃, 잎, 가루 스프라이트가 있는 경우 해당
타일을 직접 조합한다.

## 스프라이트 데이터 흐름

### 실제 앱

1. 렌더러가 기술 ID를 `pkmn:play-skill` IPC로 보낸다.
2. 메인 프로세스가 현재 `state.species`와 `state.stage`로 캐시된 골드판 PNG를 읽는다.
3. 메인 프로세스가 `effect`와 `sprite` data URL을 투명 오버레이에 전달한다.
4. 오버레이가 기술 오브젝트를 몸 중앙 기준으로 확산시킨 뒤 포켓몬을 중앙에 합성한다.

### 검수 페이지

1. 12마리를 각각 골드판 스프라이트, 이름, 단계, 기술 2개와 함께 나열한다.
2. 기술 버튼은 선택한 포켓몬의 도감 번호 기반 Gold sprite URL과 기술 ID를 iframe에 전달한다.
3. iframe은 실제 앱과 같은 오버레이 코드를 사용한다.

## 흰 배경 투명화

PokeAPI의 2세대 PNG는 알파 채널 없이 흰 배경을 포함한다. 모든 흰 픽셀을 단순 제거하면
눈과 몸의 흰색 디테일까지 사라지므로 다음 방식으로 처리한다.

1. 원본 크기의 오프스크린 Canvas에 PNG를 그린다.
2. 네 모서리와 외곽에서 시작해 RGB 각 채널이 248 이상인 픽셀을 8방향 flood-fill한다.
3. 외곽과 연결된 픽셀의 alpha만 0으로 만든다.
4. 내부 흰색은 유지하되, 검은 외곽선에 둘러싸인 32픽셀 이상의 배경 구멍은 제거한다.
5. 처리된 Canvas를 이미지별로 캐시하고 `imageSmoothingEnabled = false`로 확대한다.

이미지 로드나 픽셀 처리가 실패하면 포켓몬만 생략하고 기술은 계속 재생한다. 흰 사각형
폴백은 허용하지 않는다.

## 렌더 순서

1. Canvas 전체를 `clearRect`로 지운다.
2. 기술 오브젝트를 몸 중앙에서 화면 전체로 확대한다.
3. 투명화한 포켓몬 스프라이트를 중앙 전경에 그린다.
4. 근접 기술은 수평 이동 없이 짧은 상하 반동과 확대만 적용한다.
5. 프레임 종료 시 별도 배경색을 칠하지 않는다.

포켓몬은 8비트 비율을 유지하며 화면 높이에 따라 128~192px 범위에서 정수 배율로
확대한다. 기술 사용 중에는 같은 스프라이트를 2~4px 반동 또는 짧은 상하 이동만 적용한다.

## 투명 창 계약

- Electron `BrowserWindow`: `transparent: true`, `backgroundColor: '#00000000'`
- HTML, body, canvas: `background: transparent`
- 기술 분기에서는 화면 전체 `fillRect` 금지
- iframe과 실제 앱은 동일한 오버레이 HTML을 사용
- 화면 모서리 픽셀 alpha는 애니메이션 전체 구간에서 0이어야 한다.

## 에러 처리

- 캐시 PNG 없음: PokeAPI 다운로드를 유지하고 해당 1회는 기술만 재생한다.
- 외부 PokeAPI 실패: 갤러리는 이름과 기술 버튼을 유지하고 메타데이터만 생략한다.
- 알 수 없는 기술 ID: 투명 Canvas를 유지하고 창을 정상 종료한다.
- 연속 기술 입력: 기존 오버레이를 닫고 최신 기술 하나만 재생한다.

## 테스트와 검증

- 외곽 연결 흰색만 제거하고 내부 흰색은 보존하는 순수 함수 테스트
- 12마리 모두 서로 다른 Gold sprite URL을 갖는지 검사
- 24개 기술 모두 포켓몬 스프라이트와 함께 렌더되는지 검사
- GSC 기술 분기에서 십자선·절차적 선·전체 화면 배경 호출이 없는지 검사
- 데스크톱과 모바일 갤러리 스크린샷에서 포켓몬·기술 버튼 겹침 확인
- 대표 기술과 24개 접촉 시트에서 화면 모서리 alpha가 0인지 확인
- 전체 Vitest 통과 후 Electron 앱 재시작
